# Modèle relationnel PostgreSQL

## Objectif du document

Ce document présente la structure relationnelle de la base de données de la marketplace.

Il traduit le modèle de domaine validé en tables PostgreSQL exploitables pour le développement backend, les tests et la mise en production.

Ce document servira de référence pour :

* la création des tables PostgreSQL ;
* la génération des migrations ;
* l'implémentation des entités JPA ;
* la validation de l'intégrité des données ;
* la collaboration entre les membres de l'équipe.

---

# Principes de conception

La base de données suit les principes suivants :

* une table par entité métier principale ;
* des tables de liaison pour les relations plusieurs-à-plusieurs ;
* des tables d'historique pour les changements d'état ;
* des contraintes d'intégrité pour protéger les données ;
* des noms de tables en anglais, au pluriel, afin d'éviter les conflits avec les mots réservés PostgreSQL.

# 1. Tables d'identité et d'accès

---

## users

### Rôle

Contient les utilisateurs enregistrés sur la plateforme.

### Colonnes principales

* `id` : clé primaire
* `first_name` : prénom
* `last_name` : nom
* `email` : adresse e-mail unique
* `phone` : numéro de téléphone
* `password_hash` : mot de passe chiffré
* `status` : état du compte
* `created_at` : date de création
* `updated_at` : date de mise à jour

### Contraintes

* `email` doit être unique
* `status` doit contenir une valeur valide
* le mot de passe ne doit jamais être stocké en clair

### Relations

* un utilisateur possède plusieurs rôles
* un utilisateur possède un panier
* un utilisateur peut créer des commandes
* un utilisateur peut posséder plusieurs adresses
* un utilisateur peut créer des tickets support
* un utilisateur peut recevoir des notifications

---

## roles

### Rôle

Contient les rôles disponibles dans la marketplace.

### Colonnes principales

* `id` : clé primaire
* `code` : code du rôle (`BUYER`, `SELLER`, `DELIVERY`, `SUPPORT`, `ADMIN`)
* `name` : nom du rôle
* `description` : description fonctionnelle
* `created_at`
* `updated_at`

### Contraintes

* `code` doit être unique
* `name` doit être unique

### Relations

* un rôle peut être attribué à plusieurs utilisateurs

---

## user_roles

### Rôle

Table de liaison entre utilisateurs et rôles.

### Colonnes principales

* `user_id` : clé étrangère vers `users`
* `role_id` : clé étrangère vers `roles`
* `assigned_at` : date d’attribution

### Contraintes

* clé primaire composite (`user_id`, `role_id`)
* suppression en cascade selon la stratégie retenue

### Relations

* un utilisateur peut posséder plusieurs rôles
* un rôle peut appartenir à plusieurs utilisateurs

---

# 2. Tables du catalogue

---

## shops

### Rôle

Contient les boutiques des vendeurs.

### Colonnes principales

* `id` : clé primaire
* `owner_user_id` : utilisateur propriétaire de la boutique
* `name` : nom de la boutique
* `slug` : identifiant lisible dans l’URL
* `description` : description de la boutique
* `logo_url` : image ou logo
* `status` : état de la boutique
* `created_at`
* `updated_at`

### Contraintes

* `owner_user_id` est unique
* une boutique appartient à un seul utilisateur vendeur
* `slug` doit être unique

### Relations

* une boutique appartient à un utilisateur vendeur
* une boutique possède plusieurs produits
* une boutique est concernée par plusieurs lignes de commande

---

## categories

### Rôle

Contient les catégories de produits.

### Colonnes principales

* `id` : clé primaire
* `name` : nom de la catégorie
* `slug` : identifiant lisible dans l’URL
* `description` : description
* `is_active` : catégorie active ou non
* `created_at`
* `updated_at`

### Contraintes

* `name` doit être unique
* `slug` doit être unique

### Relations

* une catégorie contient plusieurs produits

---

## products

### Rôle

Contient les produits proposés à la vente.

### Colonnes principales

* `id` : clé primaire
* `shop_id` : boutique propriétaire
* `category_id` : catégorie du produit
* `name` : nom du produit
* `slug` : identifiant lisible dans l’URL
* `description` : description du produit
* `unit_price` : prix courant
* `currency` : devise
* `is_active` : produit actif ou non
* `created_at`
* `updated_at`

### Contraintes

* `shop_id` est obligatoire
* `category_id` est obligatoire
* `unit_price` doit être supérieur ou égal à zéro
* `slug` doit être unique par boutique ou globalement selon la règle choisie
* un produit appartient à une seule boutique
* un produit appartient à une seule catégorie

### Relations

* un produit appartient à une boutique
* un produit appartient à une catégorie
* un produit possède un stock
* un produit peut avoir plusieurs images
* un produit peut apparaître dans plusieurs lignes de panier
* un produit peut apparaître dans plusieurs lignes de commande
* un produit peut recevoir plusieurs avis

---

## product_images

### Rôle

Contient les images associées aux produits.

### Colonnes principales

* `id` : clé primaire
* `product_id` : produit concerné
* `image_url` : URL ou chemin de l’image
* `alt_text` : texte alternatif
* `sort_order` : ordre d’affichage
* `is_primary` : image principale ou non
* `created_at`

### Contraintes

* un produit peut avoir plusieurs images
* une seule image principale est recommandée par produit

### Relations

* une image appartient à un produit

---

## stocks

### Rôle

Contient l’état du stock de chaque produit.

### Colonnes principales

* `id` : clé primaire
* `product_id` : produit concerné
* `quantity_available` : quantité disponible
* `quantity_reserved` : quantité réservée
* `reorder_threshold` : seuil d’alerte
* `updated_at`

### Contraintes

* `product_id` doit être unique
* `quantity_available` ne doit pas être négatif
* `quantity_reserved` ne doit pas être négatif

### Relations

* un stock appartient à un seul produit

---

# 3. Tables du panier

---

## carts

### Rôle

Contient le panier actif d’un utilisateur.

### Colonnes principales

* `id` : clé primaire
* `user_id` : propriétaire du panier
* `status` : état du panier
* `created_at`
* `updated_at`

### Contraintes

* un utilisateur possède un seul panier actif
* `user_id` doit être unique
* un panier appartient à un seul utilisateur

### Relations

* un panier appartient à un utilisateur
* un panier contient plusieurs lignes de panier

---

## cart_items

### Rôle

Contient les produits sélectionnés dans le panier.

### Colonnes principales

* `id` : clé primaire
* `cart_id` : panier concerné
* `product_id` : produit sélectionné
* `quantity` : quantité choisie
* `unit_price_snapshot` : prix au moment de l’ajout
* `created_at`
* `updated_at`

### Contraintes

* `quantity` doit être supérieure à zéro
* un produit ne doit pas apparaître plusieurs fois dans le même panier
* une ligne de panier appartient à un seul panier

### Relations

* une ligne de panier appartient à un panier
* une ligne de panier référence un produit

---

# 4. Tables des commandes

---

## orders

### Rôle

Contient les commandes globales passées par les utilisateurs.

### Colonnes principales

* `id` : clé primaire
* `order_number` : numéro unique de commande
* `user_id` : acheteur
* `status` : état de la commande
* `total_amount` : montant total
* `currency` : devise
* `shipping_address_id` : adresse utilisée pour la livraison
* `placed_at` : date de validation
* `created_at`
* `updated_at`

### Contraintes

* `order_number` doit être unique
* `total_amount` doit être supérieur ou égal à zéro
* une commande appartient à un seul utilisateur
* une commande peut contenir des produits provenant de plusieurs boutiques

### Relations

* une commande appartient à un utilisateur
* une commande contient plusieurs lignes de commande
* une commande possède un paiement unique
* une commande possède une livraison unique

---

## order_items

### Rôle

Contient les lignes de commande.

### Colonnes principales

* `id` : clé primaire
* `order_id` : commande concernée
* `product_id` : produit acheté
* `shop_id` : boutique d’origine du produit
* `product_name_snapshot` : nom du produit au moment de l’achat
* `shop_name_snapshot` : nom de la boutique au moment de l’achat
* `quantity` : quantité achetée
* `unit_price_snapshot` : prix au moment de l’achat
* `line_total` : total de la ligne
* `created_at`

### Contraintes

* `quantity` doit être supérieure à zéro
* `unit_price_snapshot` doit être supérieure ou égale à zéro
* `line_total` doit être cohérent avec quantité × prix
* un produit ne doit apparaître qu’une fois dans une même commande, sauf choix métier contraire

### Relations

* une ligne de commande appartient à une commande
* une ligne de commande référence un produit
* une ligne de commande est liée à une boutique via le produit

---

## payments

### Rôle

Contient le paiement d’une commande.

### Colonnes principales

* `id` : clé primaire
* `order_id` : commande concernée
* `payment_reference` : référence transactionnelle
* `provider_name` : fournisseur de paiement
* `payment_method` : moyen de paiement
* `amount` : montant payé
* `currency` : devise
* `status` : état du paiement
* `paid_at` : date de paiement
* `created_at`
* `updated_at`

### Contraintes

* `order_id` doit être unique
* `amount` doit correspondre au total de la commande
* une commande possède un seul paiement

### Relations

* un paiement appartient à une seule commande

---

## deliveries

### Rôle

Contient la livraison associée à une commande.

### Colonnes principales

* `id` : clé primaire
* `order_id` : commande concernée
* `courier_user_id` : utilisateur possédant le rôle Livreur
* `address_id` : adresse de destination
* `delivery_reference` : référence de livraison
* `status` : état de livraison
* `assigned_at` : date d’affectation
* `picked_up_at` : date de récupération
* `delivered_at` : date de livraison
* `failed_reason` : motif d’échec
* `created_at`
* `updated_at`

### Contraintes

* `order_id` doit être unique
* une commande possède une seule livraison
* `courier_user_id` peut être nul tant qu’aucun livreur n’est affecté
* `courier_user_id` doit référencer un utilisateur ayant le rôle Livreur
* `address_id` est obligatoire

### Relations

* une livraison appartient à une commande
* une livraison est affectée à un utilisateur possédant le rôle Livreur
* une livraison possède une adresse de destination

---

# 5. Tables des adresses

---

## addresses

### Rôle

Contient les adresses enregistrées par les utilisateurs.

### Colonnes principales

* `id` : clé primaire
* `user_id` : propriétaire de l’adresse
* `label` : nom de l’adresse
* `recipient_name` : nom du destinataire
* `phone` : téléphone de contact
* `address_line1` : ligne 1
* `address_line2` : ligne 2
* `city` : ville
* `region` : région
* `postal_code` : code postal
* `country` : pays
* `is_default` : adresse principale ou non
* `created_at`
* `updated_at`

### Contraintes

* une adresse appartient à un seul utilisateur
* un utilisateur peut enregistrer plusieurs adresses

### Relations

* une adresse appartient à un utilisateur
* une adresse peut être utilisée par plusieurs livraisons

---

# 6. Tables des avis

---

## reviews

### Rôle

Contient les avis laissés par les utilisateurs après achat.

### Colonnes principales

* `id` : clé primaire
* `user_id` : auteur de l’avis
* `order_item_id` : ligne de commande concernée
* `product_id` : produit évalué
* `rating` : note
* `comment` : commentaire
* `created_at`
* `updated_at`

### Contraintes

* `rating` doit être compris entre 1 et 5
* un avis doit être lié à un achat réel
* un avis concerne un seul produit
* un avis ne doit pas être dupliqué sur la même ligne de commande

### Relations

* un avis appartient à un utilisateur
* un avis concerne un produit
* un avis est lié à une ligne de commande pour garantir le droit de publication

# 7. Tables du support

---

## support_tickets

### Rôle

Contient les demandes d’assistance créées par les utilisateurs.

### Colonnes principales

* `id` : clé primaire
* `ticket_number` : numéro unique du ticket
* `created_by_user_id` : utilisateur auteur
* `assigned_to_user_id` : utilisateur support en charge
* `subject` : sujet
* `description` : description du problème
* `priority` : priorité
* `status` : état du ticket
* `closed_at` : date de fermeture
* `created_at`
* `updated_at`

### Contraintes

* `ticket_number` doit être unique
* un ticket appartient à un seul utilisateur
* un ticket peut être affecté à un utilisateur Support

### Relations

* un ticket appartient à un utilisateur
* un ticket peut être pris en charge par un utilisateur Support

---

## ticket_messages

### Rôle

Contient les échanges liés à un ticket support.

### Colonnes principales

* `id` : clé primaire
* `ticket_id` : ticket concerné
* `sender_user_id` : expéditeur
* `message` : contenu du message
* `is_internal` : message interne ou visible par le client
* `created_at`

### Contraintes

* chaque message appartient à un ticket
* chaque message est envoyé par un utilisateur

### Relations

* un message appartient à un ticket
* un message est envoyé par un utilisateur

---

# 8. Tables des notifications

---

## notifications

### Rôle

Contient les notifications envoyées aux utilisateurs.

### Colonnes principales

* `id` : clé primaire
* `user_id` : destinataire
* `type` : type de notification
* `title` : titre
* `message` : contenu
* `reference_type` : type de l’objet lié
* `reference_id` : identifiant de l’objet lié
* `is_read` : lecture ou non
* `read_at` : date de lecture
* `created_at`

### Contraintes

* une notification appartient à un seul utilisateur
* le couple `reference_type` + `reference_id` permet de relier la notification à une commande, une livraison, un paiement ou un ticket

### Relations

* une notification appartient à un utilisateur

# Contraintes importantes du modèle

Les contraintes suivantes doivent être respectées :

* un utilisateur peut posséder plusieurs rôles ;
* un vendeur possède une seule boutique ;
* un produit appartient à une seule boutique ;
* une commande peut contenir des produits provenant de plusieurs boutiques ;
* une commande possède un seul paiement ;
* une commande possède une seule livraison ;
* une livraison est affectée à un utilisateur possédant le rôle Livreur ;
* une ligne de commande conserve le prix historique du produit ;
* un produit doit posséder une catégorie et un stock ;
* un avis doit être lié à un achat réel ;
* un utilisateur possède un seul panier actif.
