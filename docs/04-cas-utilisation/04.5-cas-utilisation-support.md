# Cas d'utilisation - Support

## Objectif du document

Ce document décrit les interactions possibles entre l'acteur **Support** et la marketplace.

L'objectif est d'identifier les fonctionnalités permettant au support d'assister les utilisateurs, traiter les demandes d'aide et résoudre les problèmes rencontrés sur la plateforme.

---

# Acteur concerné

## Support

Le support est un acteur chargé d'accompagner les utilisateurs de la marketplace.

Il intervient auprès de :

- acheteurs ;
- vendeurs ;
- livreurs.

Son rôle principal est de :

- recevoir les demandes d'assistance ;
- analyser les problèmes signalés ;
- communiquer avec les utilisateurs ;
- suivre la résolution des incidents.

---

# Objectifs principaux du support

Le support doit pouvoir :

- gérer les demandes d'assistance ;
- communiquer avec les utilisateurs ;
- traiter les réclamations ;
- suivre les problèmes jusqu'à leur résolution ;
- consulter les informations nécessaires à l'analyse.

# Description détaillée des cas d'utilisation

---

# UC-S01 — Accéder à l'espace support

## Objectif

Permettre au support d'accéder aux outils nécessaires à son activité.

## Acteur principal

Support

## Préconditions

- L'utilisateur possède un compte.
- Le rôle Support lui est attribué.

## Actions principales

1. Le support se connecte à la plateforme.
2. Le système vérifie ses permissions.
3. L'espace support devient accessible.

## Résultat attendu

Le support peut gérer les demandes utilisateurs.

---

# UC-S02 — Consulter les demandes d'assistance

## Objectif

Permettre au support de visualiser les demandes reçues.

## Informations consultables

- utilisateur concerné ;
- sujet de la demande ;
- date de création ;
- priorité ;
- état du traitement.

## Résultat attendu

Le support dispose d'une liste des demandes à traiter.

---

# UC-S03 — Créer un ticket support

## Objectif

Permettre au support d'enregistrer une nouvelle demande.

## Cas possibles

Exemples :

- problème de commande ;
- problème de livraison ;
- problème de compte ;
- question générale.

## Actions principales

1. Le support saisit les informations nécessaires.
2. Le ticket est enregistré.
3. Le suivi du traitement commence.

## Résultat attendu

Une demande d'assistance est créée.

---

# UC-S04 — Modifier le statut d'un ticket

## Objectif

Permettre au support de suivre l'évolution d'une demande.

## Exemple de statuts

- Nouveau ;
- En cours de traitement ;
- En attente d'information ;
- Résolu ;
- Fermé.

## Résultat attendu

L'état du ticket reflète son avancement réel.

---

# UC-S05 — Répondre à un utilisateur

## Objectif

Permettre au support de communiquer avec l'utilisateur ayant envoyé une demande.

## Actions principales

Le support peut :

- envoyer une réponse ;
- demander des informations complémentaires ;
- informer de la résolution.

## Résultat attendu

L'utilisateur reçoit une assistance adaptée.

---

# UC-S06 — Consulter l'historique d'un ticket

## Objectif

Permettre au support de consulter les échanges précédents.

## Informations consultables

- messages précédents ;
- actions réalisées ;
- changements de statut ;
- intervenants.

## Résultat attendu

Le support possède le contexte complet du problème.

---

# UC-S07 — Traiter une réclamation

## Objectif

Permettre au support de gérer les problèmes signalés par les utilisateurs.

## Exemples de réclamations

- commande non reçue ;
- produit incorrect ;
- problème avec un vendeur ;
- problème avec une livraison.

## Actions principales

1. Le support analyse la situation.
2. Il consulte les informations nécessaires.
3. Il propose une résolution.

## Résultat attendu

La réclamation est traitée selon les règles de la plateforme.

---

# UC-S08 — Consulter les informations nécessaires

## Objectif

Permettre au support d'obtenir les informations utiles pour résoudre un problème.

## Informations accessibles

Selon les permissions :

- informations publiques utilisateur ;
- informations de commande ;
- informations de livraison ;
- historique des échanges.

## Restrictions

Le support ne peut pas :

- modifier les données commerciales sans autorisation ;
- accéder aux informations sensibles non nécessaires ;
- modifier les paramètres système ;
- gérer les comptes administrateurs.
