# Diagramme des cycles métier

## Objectif du document

Ce document présente les principaux cycles métier de la marketplace.

Il décrit l'évolution des objets métier importants depuis leur création jusqu'à leur finalisation.

Les cycles métier permettent de représenter :

- les états successifs des objets métier ;
- les actions déclenchant les changements d'état ;
- les acteurs responsables des transitions ;
- les règles métier associées.

Ce document servira de référence pour :

- les diagrammes d'états UML ;
- la conception des services métier ;
- la définition des règles de gestion ;
- l'implémentation des workflows applicatifs.

---

# Principe général des cycles métier

La marketplace repose sur plusieurs processus métier principaux :

- Cycle de vie d'une commande ;
- Cycle de vie d'une livraison ;
- Cycle de vie d'un paiement ;
- Cycle de traitement des tickets support.

Les acteurs intervenant dans ces processus sont représentés par des rôles associés à l'entité Utilisateur :

- Acheteur ;
- Vendeur ;
- Livreur ;
- Support ;
- Administrateur.

Un même utilisateur peut posséder plusieurs rôles.

Exemples :

- un utilisateur peut être Acheteur et Vendeur ;
- un utilisateur peut être Acheteur et Livreur.

---

# 1. Cycle de vie d'une commande

## Objectif

Ce cycle décrit l'évolution d'une commande depuis la validation du panier jusqu'à sa finalisation.

---

# Principe métier

Un utilisateur peut ajouter dans son panier des produits provenant de plusieurs boutiques.

Lors de la validation :

- le système vérifie la disponibilité des produits ;
- le montant total est calculé ;
- un paiement unique est effectué ;
- une commande globale est créée.

La commande reste unique pour l'acheteur même si plusieurs boutiques participent au traitement.

---

# États d'une commande

| État                      | Description                                                       |
| Créée                     | La commande est générée après validation du panier.               |
| En attente de paiement    | La commande existe mais le paiement n'est pas encore confirmé.    |
| Payée                     | Le paiement a été validé.                                         |
| En préparation            | Les vendeurs préparent les produits concernés.                    |
| Expédiée                  | Les produits préparés sont transmis au processus logistique.      |
| En livraison              | La commande est transportée vers l'acheteur.                      |
| Livrée                    | L'acheteur a reçu la commande.                                    |
| Terminée                  | Le processus commercial est clôturé.                              |
| Annulée                   | La commande est interrompue selon les règles métier.              |

# Description des étapes

## Création

Déclencheur :

Validation du panier par l'acheteur.

Actions :

- contrôle des stocks ;
- création de la commande ;
- création des lignes de commande ;
- calcul du montant total.

Acteur principal :

Utilisateur Acheteur / Système.

---

## Paiement

Déclencheur :

Validation du paiement.

Actions :

- confirmation du règlement ;
- changement d'état de la commande ;
- notification des vendeurs concernés.

Acteur principal :

Utilisateur Acheteur / Système.

---

## Préparation

Déclencheur :

Paiement confirmé.

Actions :

- chaque vendeur prépare ses produits ;
- le système suit l'avancement global.

Acteur principal :

Utilisateur possédant le rôle Vendeur.

---

## Expédition

Déclencheur :

Tous les produits nécessaires sont préparés.

Actions :

- regroupement des produits ;
- création ou activation du processus de livraison.

Acteur principal :

Système.

---

## Livraison

Déclencheur :

Affectation d'un utilisateur possédant le rôle Livreur.

Actions :

- transport de la commande ;
- mise à jour du suivi ;
- confirmation de réception.

Acteur principal :

Utilisateur possédant le rôle Livreur.

---

# 2. Cycle de vie d'une livraison

## Objectif

Ce cycle décrit l'évolution d'une livraison associée à une commande.

---

# Principe métier

Une commande possède une seule livraison.

La livraison concerne l'ensemble des produits de la commande, même lorsque plusieurs boutiques sont impliquées.

Il correspond à :

Utilisateur + rôle Livreur

---

# États d'une livraison

| État                      | Description                                           |
| Créée                     | La livraison est générée par le système.              |
| En attente d'affectation  | Aucun utilisateur Livreur n'est encore attribué.      |
| Affectée                  | Un utilisateur Livreur est responsable.               |
| En récupération           | Le livreur récupère la commande préparée.             |
| En livraison              | Le transport vers l'acheteur est en cours.            |
| Livrée                    | La commande est remise à l'acheteur.                  |
| Échec                     | La livraison n'a pas pu être réalisée.                |
| Annulée                   | La livraison est arrêtée selon les règles métier.     |

# Description des étapes

## Création

Le système crée une livraison lorsque la commande est prête.

Actions :

- association avec la commande ;
- définition de l'adresse ;
- initialisation du statut.

---

## Affectation

Un utilisateur possédant le rôle Livreur est affecté.

Relations :

Utilisateur (rôle Livreur)
             |
             |
        Livraison

Règle :

Une livraison possède un seul livreur actif à un instant donné.

---

## Transport

Le livreur :

- récupère la commande ;
- transporte les produits ;
- met à jour l'état.

---

## Réception

L'acheteur reçoit la commande.

Actions :

- confirmation de livraison ;
- passage à l'état Livrée ;
- clôture de la commande.

# 3. Cycle de vie d'un paiement

## Objectif

Décrire le traitement financier d'une commande.

---

# États d'un paiement

| État          | Description                                       |
| Créé          | Le paiement est généré avec la commande.          |
| En attente    | Le paiement attend une confirmation.              |
| Accepté       | Le paiement est validé.                           |
| Refusé        | Le paiement a échoué.                             |
| Remboursé     | Le paiement est retourné selon les règles métier. |

# 4. Cycle de traitement des tickets support

## Objectif

Décrire le traitement d'une demande d'assistance.

---

# États d'un ticket

| État              | Description                               |
| Ouvert            | Le ticket vient d'être créé.              |
| Pris en charge    | Un utilisateur Support traite la demande. |
| En traitement     | Une analyse ou une action est en cours.   |

# Relations avec le modèle de domaine

Les cycles métier utilisent les entités suivantes :

| Cycle     | Entités principales                                       |
| Commande  | Utilisateur, Panier, Ligne commande, Paiement, Livraison  |
| Livraison | Livraison, Commande, Adresse, Utilisateur (rôle Livreur)  |
| Paiement  | Paiement, Commande                                        |
| Support   | Ticket support, Utilisateur                               |

---

# Règles métier importantes

Les règles suivantes doivent être respectées :

- Une commande appartient à un seul utilisateur acheteur.
- Une commande possède un seul paiement.
- Une commande possède une seule livraison.
- Un utilisateur peut posséder plusieurs rôles.
- Le rôle Livreur appartient à l'utilisateur et non à une entité indépendante.
- Une livraison est affectée à un utilisateur possédant le rôle Livreur.
- Une commande peut contenir des produits provenant de plusieurs boutiques.
- Les vendeurs ne traitent que les produits appartenant à leur boutique.
- Le paiement concerne la commande globale.
- La livraison concerne la commande globale.
