# Modèle de domaine

## Objectif du document

Ce document présente le modèle de domaine métier de la marketplace.

Il représente les principales entités métier du système ainsi que leurs relations et leurs responsabilités.

Le modèle de domaine permet de traduire les règles métier en une représentation structurée des concepts manipulés par la plateforme.

Il servira de référence pour :

- le diagramme de classes métier ;
- la conception du modèle conceptuel de données (MCD) ;
- la conception des entités Java ;
- l'implémentation des services métier.

---

# Principe du modèle de domaine

La marketplace repose sur une entité centrale :

- Utilisateur.

Les différents profils de la plateforme sont représentés par des rôles associés aux utilisateurs :

- Acheteur ;
- Vendeur ;
- Livreur ;
- Support ;
- Administrateur.

Un même utilisateur peut cumuler plusieurs rôles selon les permissions qui lui sont attribuées.

Exemples :

- un utilisateur peut être Acheteur et Vendeur ;
- un utilisateur peut être Acheteur et Livreur.

Le domaine est organisé autour des concepts principaux suivants :

- Utilisateur ;
- Rôle ;
- Boutique ;
- Produit ;
- Catégorie ;
- Stock ;
- Panier ;
- Commande ;
- Paiement ;
- Livraison ;
- Adresse ;
- Avis ;
- Ticket support ;
- Notification.

# Entités principales du domaine

---

# Utilisateur

## Description

L'utilisateur représente une personne enregistrée sur la plateforme.

Il constitue l'entité centrale du système.

Les différents acteurs métier sont représentés par les rôles associés à cet utilisateur.

## Responsabilités métier

Un utilisateur peut :

- gérer son compte ;
- posséder plusieurs rôles ;
- posséder plusieurs adresses ;
- effectuer des commandes ;
- gérer une boutique s'il possède le rôle vendeur ;
- recevoir des notifications ;
- créer des tickets support ;
- publier des avis selon les règles métier ;
- effectuer des livraisons s'il possède le rôle livreur.

## Relations principales

Un utilisateur :

- possède un ou plusieurs rôles ;
- peut posséder une boutique s'il possède le rôle vendeur ;
- possède un panier actif ;
- effectue plusieurs commandes ;
- possède plusieurs adresses ;
- reçoit plusieurs notifications ;
- crée plusieurs tickets support ;
- peut être affecté à plusieurs livraisons s'il possède le rôle Livreur.

---

# Rôle

## Description

Le rôle définit les responsabilités et permissions associées à un utilisateur.

## Rôles disponibles

Les rôles principaux sont :

- Acheteur ;
- Vendeur ;
- Livreur ;
- Support ;
- Administrateur.

## Responsabilités métier

Le rôle permet de contrôler les actions accessibles sur la plateforme.

Exemples :

- un utilisateur avec le rôle Vendeur peut gérer une boutique ;
- un utilisateur avec le rôle Livreur peut effectuer des livraisons ;
- un utilisateur avec le rôle Support peut traiter des tickets.

---

# Boutique

## Description

La boutique représente l'espace commercial d'un vendeur sur la marketplace.

Elle regroupe les produits proposés à la vente.

## Responsabilités métier

Une boutique permet :

- de publier des produits ;
- de gérer les informations commerciales ;
- de suivre les ventes associées aux produits.

## Relations principales

Une boutique :

- appartient à un seul utilisateur possédant le rôle Vendeur ;
- possède plusieurs produits.

---

# Produit

## Description

Le produit représente un article proposé à la vente sur la marketplace.

Chaque produit appartient obligatoirement à une boutique.

## Responsabilités métier

Un produit possède notamment :

- un nom ;
- une description ;
- un prix ;
- une ou plusieurs images ;
- une catégorie ;
- un stock disponible.

## Relations principales

Un produit :

- appartient à une boutique ;
- appartient à une catégorie ;
- possède un stock ;
- peut apparaître dans plusieurs lignes de panier ;
- peut apparaître dans plusieurs lignes de commande ;
- peut recevoir plusieurs avis.

---

# Catégorie

## Description

La catégorie permet de classer les produits de la marketplace.

## Responsabilités métier

Les catégories permettent :

- l'organisation du catalogue ;
- la recherche des produits ;
- la navigation des acheteurs.

## Relations principales

Une catégorie :

- contient plusieurs produits.

---

# Stock

## Description

Le stock représente la quantité disponible d'un produit.

## Responsabilités métier

Le stock permet :

- de connaître la disponibilité d'un produit ;
- de contrôler les quantités commandées.

## Relations principales

Un stock :

- appartient à un seul produit.

---

# Panier

## Description

Le panier représente l'ensemble des produits sélectionnés par un utilisateur avant validation d'une commande.

## Responsabilités métier

Le panier permet :

- d'ajouter des produits ;
- de modifier les quantités ;
- de préparer la création d'une commande.

## Relations principales

Un panier :

- appartient à un utilisateur ;
- contient plusieurs lignes de panier.

---

# Ligne de panier

## Description

La ligne de panier représente un produit sélectionné avec une quantité donnée.

## Responsabilités métier

Elle conserve :

- le produit choisi ;
- la quantité demandée.

## Relations principales

Une ligne de panier :

- appartient à un panier ;
- référence un produit.

---

# Commande

## Description

La commande représente l'achat global réalisé par un utilisateur.

Elle reste unique même lorsque les produits proviennent de plusieurs boutiques.

## Principe multi-boutiques

Une commande peut contenir :

- des produits d'une seule boutique ;
- des produits provenant de plusieurs boutiques.

La commande reste un seul processus commercial pour l'utilisateur.

## Responsabilités métier

Une commande permet :

- de suivre l'achat ;
- de gérer le paiement ;
- de suivre la préparation ;
- de suivre la livraison.

## Relations principales

Une commande :

- appartient à un utilisateur ;
- contient plusieurs lignes de commande ;
- possède un paiement unique ;
- possède une livraison unique.

---

# Ligne de commande

## Description

La ligne de commande représente un produit acheté dans une commande.

Elle conserve les informations historiques de l'achat.

## Informations conservées

Une ligne de commande contient notamment :

- le produit acheté ;
- la quantité ;
- le prix au moment de l'achat ;
- la boutique d'origine du produit.

## Relations principales

Une ligne de commande :

- appartient à une commande ;
- référence un produit ;
- est liée à une boutique par le produit acheté.

---

# Paiement

## Description

Le paiement représente le règlement financier d'une commande.

## Principe métier

Une commande possède un paiement unique.

Le paiement correspond au montant total de la commande, même si plusieurs boutiques sont concernées.

## Relations principales

Un paiement :

- appartient à une seule commande.

---

# Livraison

## Description

La livraison représente le processus d'acheminement d'une commande vers l'utilisateur.

## Principe métier

Une commande globale possède une seule livraison.

La livraison concerne l'ensemble des produits regroupés après préparation par les différentes boutiques.

## Responsabilités métier

Une livraison permet :

- l'affectation d'un utilisateur possédant le rôle Livreur ;
- le suivi du transport ;
- la confirmation de réception.

## Relations principales

Une livraison :

- appartient à une commande ;
- est affectée à un utilisateur ayant le rôle Livreur ;
- possède une adresse de destination.

---

# Adresse

## Description

L'adresse représente une localisation utilisée pour les livraisons.

## Responsabilités métier

Une adresse permet :

- la livraison des commandes ;
- la gestion de plusieurs destinations.

## Relations principales

Une adresse :

- appartient à un utilisateur ;
- peut être utilisée par plusieurs livraisons.

---

# Avis

## Description

L'avis représente une évaluation laissée par un utilisateur après un achat.

## Responsabilités métier

Un avis permet :

- d'évaluer un produit ;
- de partager un retour d'expérience.

## Relations principales

Un avis :

- appartient à un utilisateur ;
- concerne un produit.

---

# Ticket support

## Description

Le ticket support représente une demande d'assistance créée par un utilisateur.

## Responsabilités métier

Un ticket permet :

- de signaler un problème ;
- de suivre une demande ;
- d'être traité par un utilisateur ayant le rôle Support.

## Relations principales

Un ticket :

- appartient à un utilisateur ;
- peut être pris en charge par un utilisateur Support.

---

# Notification

## Description

La notification représente une information envoyée à un utilisateur lors d'un événement important.

## Exemples

- confirmation de paiement ;
- changement de statut d'une commande ;
- évolution d'une livraison ;
- réponse du support.

## Relations principales

Une notification :

- appartient à un utilisateur.

# Contraintes importantes du modèle

Les contraintes suivantes doivent être respectées :

- Un utilisateur peut posséder plusieurs rôles.
- Un vendeur possède une seule boutique.
- Un produit appartient à une seule boutique.
- Une commande peut contenir des produits provenant de plusieurs boutiques.
- Une commande possède un seul paiement.
- Une commande possède une seule livraison.
- Une livraison est affectée à un utilisateur possédant le rôle Livreur.
- Une ligne de commande conserve le prix historique du produit.
- Un produit doit posséder une catégorie et un stock.
